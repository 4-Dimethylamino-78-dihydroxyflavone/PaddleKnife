## 1. Summary

- **The engine is in good shape.** Plans 5–9 produced a character-correct
  glyphless text layer, a data-driven multi-script registry, rotated-text
  geometry and PP-OCRv6. Library code has almost no `unwrap`/`panic` and no
  `unsafe` (on `main`).
- **The biggest risk is unmerged work.** Plan 10 (OOM resilience + page
  orientation verification) and the embed-size fix have lived only in
  worktrees since 2026-09-21. Until they land, `main` has two known
  user-facing bugs:
  - `--detect-page-orientation` can blank Devanagari pages.
  - Screenshot PDFs can bloat ~10×.
- **The biggest gap is on-ramp and repeatability.**
  - The README still documents the Python tool.
  - A fresh install cannot find its models (§5, High).
  - `Cargo.lock` is gitignored and there is no CI.
- **Disk:** 80.5 of 82.6 GB was Cargo build cache duplicated per worktree.
  About 55 GB has been reclaimed so far (§2).

## 2. Disk: why the worktrees reached 80 GB

| Checkout | Total | `target/` | of which `.pdb` debug info |
|---|---|---|---|
| main | 26.8 GB | 25.7 GB | 8.75 GB (124 files) |
| paddleknife-ocrv6-upgrade | 17.1 GB | 16.7 GB | — |
| zealous-franklin | 12.1 GB | 12.0 GB | — |
| paddleknife-directory-formats | 10.2 GB | 10.1 GB | — |
| amazing-bhabha | 8.5 GB | 8.2 GB | — |
| thirsty-cannon | 8.0 GB | 7.8 GB | — |
| `.git` (shared) | 0.94 GB | — | 1.27 GB TrOCR blob in a stash |

Three mechanisms compounded:

1. **One `target/` per worktree.** Each worktree has its own
   `Cargo.toml`, so each gets its own build directory.
2. **Cargo never garbage-collects `target/`.** Main's `deps/` holds
   **10 copies of `oar_ocr`** and 9 of `paddleknife_core`: every version
   bump (0.6.2 → 0.8.1 → vendored) and feature combination left its
   artifacts behind.
3. **Windows/MSVC debug info.** Every integration-test binary (10) and
   example (4) links the full ort + image + pdfium stack and gets its own
   PDB.

Separately, a 2026-05-22 `git stash -u` swept an untracked 1.27 GB
`model.safetensors` into `.git` and pinned it there. A crashed repack also
left a 150 MB `tmp_pack`.

**Done 2026-09-30:**

- Removed the 4 fully-merged worktrees (branches kept).
- Deleted `target/` in the 2 unmerged worktrees.
- Committed the untracked ADR-0002, tagged the stash's orphan base commit
  `archive/trocr-force-cpu-a8915b2`, dropped the stash and ran `git gc`.
  `.git` went from 964 MB to 18 MB.

**Prevention (pending, see §8 item 1):**

- A local, uncommitted `.cargo\config.toml` in the main checkout
  with `build.target-dir = "target"` and `[env] PDFIUM_LIB_PATH`. Every
  worktree under the main checkout then inherits one shared build directory
  and main's pdfium.
- Later, once both branches are merged, one `cargo clean` in main resets the
  ten stale oar-ocr builds.

### 4.1 Plan 10 — `claude/paddleknife-ocr-pipeline-1bdb54`: mergeable as-is

  screenshots (fixed by Plan 10), and `models pull` doesn't fetch
  `pp-lcnet_x1_0_doc_ori.onnx`, so on a fresh install it silently no-ops.
- Stale comments:
  - `searchable_pdf/mod.rs:12-15` still describes per-cluster `Tz`.
  - `cli.rs:264` and `ocr.rs:369,372` say GPU batch 32; the code uses 64.
  - `cli.rs:1-4` promises `batch`, `info` and `surya-inject`.
  - `models/README.md` calls textline_ori 4-way (it's 2-class) and says the
    Devanagari model is "Python only".
- **Plan docs:**
  - They're split by the tool that wrote them (`docs/plans/` vs
    `docs/superpowers/`).
  - They contain 151 unticked checkboxes.
  - Plans 1 + 8 are 4,174 lines, 2,863 of them stale code snapshots.
  - Plans 7 and 9 have no document.

**Consolidation proposal.** Replace the plan sprawl with three living files:

- `docs/ARCHITECTURE.md`: pipeline, contracts, invariants, gates.
- `docs/DECISIONS.md`: one paragraph per plan/ADR with its measured
  outcome, i.e. §3 of this audit.
- The branch ledger.

Move the full plans to `docs/archive/plans/`. Knowledge that never got
a plan doc (pdfium GID-1, quad ordering, memory law, doc_ori misfire) belongs in
ARCHITECTURE.md, where every contributor sees it.

## 7. Build reproducibility

| Issue | Consequence | Fix |
|---|---|---|
| `Cargo.lock` gitignored | Fresh resolves pick up oar-ocr 0.6.3 / ort rc.13, which don't compile together. Every worktree needed the lock copied by hand. | Commit it (Cargo's default for binaries) |
| `rust-toolchain.toml` = `stable` | Floats past the tested version | Pin e.g. `1.96.0` |
| pdfium from `releases/latest` | Unpinned; `pdf.rs:32,42` only knows `pdfium.dll` | Pin a release tag; honour platform names |
| Models from `/resolve/main/` + raw `main`, size-only check | An upstream dict change silently garbles output (`model.rs` warns about exactly this) | Pin revisions + SHA-256 (oar-ocr's registry already has them) |
| Integration tests `.expect("models present")` | Fresh clones fail instead of skipping | Skip with a message when models are absent |
| No CI | Regressions surface only on this machine | One Windows job for the model-free tests (`cargo test --lib` + fixtures) |

## 9. Working rules this audit adds

- **Never `git stash -u`** while `models/` can hold unignored weights. Use a
  WIP commit instead. The stash stack is shared by every worktree.
- **Commit research the day it's written.** ADR-0002 sat untracked for two
  months in a worktree that was one cleanup away from deletion.
- **Merge or archive within a week.** Every worktree left open is a
  10–25 GB build cache plus a knowledge silo. Record each branch in the
  ledger when it closes.
- **Measure disk with `robocopy /L` or `Get-ChildItem`, not MSYS `du`,** on
  multi-GB `target/` trees; `du` ran >10 minutes without finishing.
